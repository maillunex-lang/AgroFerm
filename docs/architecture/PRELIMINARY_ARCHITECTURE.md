# Предварительная архитектура

Статус документа: `PROPOSED`. Не является `APPROVED`. Код по этому файлу не писать.

Проверка на 2026-11-11: репозиторий был пуст, стек ниже выбран как кандидат, потому что он совпадает с постановкой и не требует микросервисов.

## Кандидаты

| Слой | Кандидат | Не делать сейчас |
|---|---|---|
| Клиент | Godot 4.7.2, GDScript, ландшафтная ориентация | C# / .NET на клиенте: тяжелее экспорт и не нужен |
| Сервер | Go, один процесс, модули по доменам | Микросервисы, отдельный сервер физики республики |
| Данные | PostgreSQL. Деньги и количества — `BIGINT` | `float` для денег. Redis до измерения |
| Сеть | HTTPS для входа и админки, WebSocket для сессии | Самописный UDP, пока нет ручной техники и измерений |
| Админка | React + TypeScript, отдельное приложение, тот же API | Прямой доступ к БД из браузера |
| Запуск стенда | Docker Compose, Caddy или Nginx | Kubernetes |
| CI | GitHub Actions, когда появится первая команда теста | Обязательный деплой в прод из каждой ветки |

Godot 4.8 не кандидат, пока не выйдет stable. Рендерер (Forward+, Mobile, Compatibility) не фиксируется: переключение на Android требует проверки перезапуска и профиля. Это [Q-TECH-002](../design/D10-tech.md).

## Как делится ответственность

Сервер хранит и решает:

- аккаунт и сессию;
- хозяйство, участки, посевы, склады;
- технику как записи: состояние, топливо, износ, задание;
- здания, производство, контракты, рынок;
- кооператив, квесты, награды;
- ИИ-компании как те же доменные записи с пометкой `controller = ai`;
- время мира.

Клиент решает:

- кадр, камеру, звук, локальные подсказки;
- отправку намерения («посеять», «вести трактор», «выставить заявку»);
- предсказание положения своей машины только для картинки. Расхождение правит сервер.

Админка решает:

- черновики справочников;
- публикацию версии контента;
- поддержку игрока через те же команды, что и игра, с аудитом.

Админка не делает `UPDATE` по критичным таблицам в обход сервиса.

## Модули сервера

Один бинарник. Граница модуля — пакет и таблицы, которыми он владеет. Чужие таблицы напрямую не менять.

`auth` `account` `session` `world` `land` `farming` `livestock` `machinery` `construction` `production` `inventory` `ledger` `market` `logistics` `contract` `cooperative` `ai` `event` `quest` `monetization` `admin` `content` `audit`

На срезе №1 живут только: `auth`, `account`, `session`, `world` (минимальные часы), `land` (один участок), `farming` (одна культура, одна операция), `machinery` (одна машина без физики парка), `inventory`, `ledger`, `admin`, `audit`. Остальные пакеты не создавать заранее.

## Симуляция

Непрерывной физики республики нет.

- Хозяйственные процессы — отложенные записи `due_at`. Рабочий цикл сервера подбирает наступившие и применяет их в транзакции.
- Игрок офлайн не «тикает» каждый кадр. При входе и по расписанию сервер досчитывает интервал от `last_resolved_at` до `min(now, cap)`. Потолок офлайн-прогресса — вопрос D2, не константа в этом файле.
- Рынок пересчитывается по расписанию, не на каждый чих клиента.
- Грузовик между районами — запись рейса с временем прибытия, не объект в 3D.
- Ручная работа на поле, когда её добавят, шлёт намерения часто, но урожай начисляется один раз, когда сервер признал операцию завершённой по правилам участка.

Так сервер остаётся источником истины и не считает республику в 60 Гц.

## Данные

- Идентификаторы: UUID.
- Деньги и доли ресурсов: целые. Имя валюты и масштаб (1 единица = 100 минимальных или иначе) задаёт D3.
- Каждая хозяйственная команда: `command_id` от клиента, уникальность в базе, повтор возвращает прошлый результат.
- Журнал экономики append-only: кто, что, до, после, команда, время. Правка баланса без записи журнала запрещена.
- Справочники контента версионируются. Игровая сессия знает номер версии. Несовместимый клиент не входит в мир.
- Миграции только вперёд файлами. Ручные правки схемы на стенде не считаются.

ER-диаграмму рисовать на этапе 2 для таблиц среза №1, не для всех 40 систем сразу.

## Сеть, коротко

Точный формат кадров — вопрос [Q-TECH-003](../design/D10-tech.md). Пока достаточно границ:

- пароль не в репозитории и не в логе;
- после пароля — сессия, не вечный токен в запросных параметрах;
- админские методы отдельно от игровых, с ролью;
- частота игровых намерений ограничена;
- ошибка доменного правила возвращается текстом кода, клиент не «чинит» её локальным начислением.

## Клиент и Android

- Стартовая сборка тонкая: вход, загрузчик, обязательный минимум. Остальные паки качаются после установки. Цель ≤ 95 МБ — цель, не обещание.
- Пак контента: версия, манифест, контрольная сумма. Докачка. Битый файл качается снова. Исполняемый код паками не доставляется.
- Обновление APK — через механизм установки Android, с согласием. Подпись релиза вне git.
- Профили графики: минимальный, низкий, средний, высокий, авто. Авто выбирает профиль на устройстве и запоминает. Цифры FPS записать только после прогона.
- MultiMesh, LOD, пулы и стриминг применять там, где профиль это оправдывает, а не списком «включено всё».

## Среды

`dev` и `staging` не используют базу `prod` и не ходят на платёжный боевой контур. Иначе тестовый посев меняет живую экономику. Отдельного боя ещё нет, правило фиксируется до первого деплоя.

## Что сознательно отложено

Шардирование, Redis, отдельный симулятор как сервис, генеративный ИИ в диалогах, античит ядра руля, голосовой чат, ПК-клиент.
