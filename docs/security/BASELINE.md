# Базовая безопасность

Правила до появления кода. Нарушение любого пункта блокирует задачу.

1. Секреты, токены, пароли БД и релизный keystore в git не хранятся. Пример в документации — заглушка, не настоящий секрет.
2. Игрок не присылает «начислить 100 зерна». Он присылает намерение. Сервер считает результат.
3. Хозяйственная операция идемпотентна по идентификатору команды.
4. Списание и начисление одной сделки — одна транзакция. Падение посреди сделки не оставляет плюс без минуса.
5. Баланс не уходит ниже нуля, если правило явно не разрешило долг. Долг — отдельное решение D3/D4, не побочный эффект типа.
6. Админ не правит критичную таблицу SQL-консолью как штатным способом. Есть команда и запись аудита.
7. Тестовый стенд не подключён к производственной базе.
8. Контент-паки не содержат исполняемый код и не принимаются без проверки целостности.
9. ИИ-профиль помечен. Нельзя оформлять бота как живого игрока.
10. Ввод в чат, названия хозяйства и эмблемы считать недоверенными: ограничение длины, никакой разметки, которая исполняется.

Проверки появятся вместе с кодом: повтор команды, отрицательный остаток, две параллельные покупки последнего лота, обрыв между списанием и выдачей. Пока кода нет, этот файл не считается проверенным контролем, только нормой.
