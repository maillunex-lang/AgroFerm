# PHASE-03. Вертикальный срез №1

- Статус: `NOT_STARTED`
- Готовность: 0%
- Зависит от: PHASE-02 принят как задание на реализацию.
- Блокеры: проектирование не закончено. Этот файл — рамка, не разрешение писать код.

## 1. Цель

Один игрок на Android (или экспорт, который реально запускается) входит на сервер, заводит хозяйство, выполняет одну сельскохозяйственную операцию на одном поле, видит результат после повторного входа. Сервер — источник урожая и денег, если деньги в этом срезе уже разрешены D3. Если D3 не закрыт к моменту среза, денежная операция заменяется одной серверной наградой с журналом, а название валюты не выдумывается в интерфейсе: «награда» без курса.

## 2. Состав

Обязательное из постановки:

1. Запуск Android-клиента.
2. Авторизация.
3. Подключение к серверу.
4. Создание хозяйства.
5. Одна игровая территория.
6. Одно поле.
7. Одна культура. Кандидат — пшеница, если Q-FARM-002 не выберет иное.
8. Один трактор. Карточка и занятость, без физики, если Q-MECH-002 останется «руль позже».
9. Одна операция. Кандидат — назначить работу и получить результат сервером.
10. Серверное сохранение.
11. Простейшая экономика: одна операция журнала.
12. Минимальная веб-админка: вход, хозяйство, культура, журнал, флаг техработ.
13. Повторный вход восстанавливает то же хозяйство.

Карты республики нет, см. рекомендацию Q-WORLD-007. Это не утверждено, пока вопрос не задан и не отвечен.

## 3. Зависимости

SYS-AUTH, SYS-SESSION, SYS-FARM, SYS-WORLD в минимальном виде, SYS-LAND, SYS-CROP, SYS-INV, SYS-MACH, SYS-LEDGER, SYS-AUDIT, SYS-CONTENT, узкий SYS-TUTOR. См. каталог.

## 5. API

Не фиксируется здесь. На PHASE-02 описываются команды намерений, не готовые URL. Любая команда несёт `command_id`. Повтор возвращает прежний результат.

Черновой список намерений, не контракт: зарегистрироваться, войти, создать хозяйство, назначить операцию, забрать результат, восстановить сессию.

## 6. Данные

UUID, целые количества, журнал append-only, уникальность `command_id`. ER — на PHASE-02. Здесь нельзя создавать таблицы «на вырост» под животных и рынок.

## 7. UI

Экраны: загрузка, вход, создание хозяйства, двор с одним полем, карточка операции, ошибка сети, техработы. Пустое состояние и повтор. Остальные 20 экранов постановки не делать.

Управление: камера и выбор поля. Руля нет, пока его не перенесли в этот срез отдельным решением.

## 8. Админка

Просмотр хозяйства, правка справочника одной культуры через черновик и публикацию, просмотр журнала, выдача тестовой награды только командой с аудитом, флаг техработ.

## 9. Тесты

- повтор `command_id` не удваивает урожай и награду;
- чужое поле нельзя обработать;
- обрыв сокета и второй вход показывают тот же остаток;
- две параллельные попытки завершить одну операцию дают один результат;
- несовместимая версия клиента не входит в мир;
- миграция на чистой базе поднимается с нуля.

## 10. Критерий готовности

Человек проходит сценарий на сборке Android и на втором входе видит тот же результат. Админ видит журнал этой операции. Команды проверки из репозитория запущены и их вывод сохранён в отчёте этапа. Без этого статус не `VERIFIED`.

## 11. Ограничения

Нет карты края, второй культуры, работников, износа, топлива, животных, рынка игроков, чата, кооператива, платежей, ИИ-фермеров. Офлайн-досчёт может быть выключен, если так решён Q-TIME-005 для прототипа.

## 12. Команды проверки

Появятся в файле этапа вместе с кодом. Сейчас их нет, и писать, что они зелёные, нельзя. Ожидаемый минимум: тесты сервера одной командой, сборка админки, экспорт клиента. Имена команд не выдумывать, пока нет проекта.

## 13. Откат

До внешнего игрока: снести базу стенда и поднять миграции заново. После чужого прогресса: возврат к снимку по правилу Q-OPS-004, не «починить руками UPDATE». Откат версии контента — предыдущий опубликованный номер, клиент его ещё понимает, иначе это уже обязательное обновление APK.
