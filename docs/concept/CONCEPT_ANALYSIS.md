# Разбор концепции

Источник: постановка «АгроБашкирия Online: Наследие земли». Это разбор, не GDD и не утверждение механик.

## Сильные стороны

- Ясный фантазийный и географический якорь: своё хозяйство в Башкортостане, а не безликая ферма.
- Правильный авторитет сервера. Экономику нельзя честно сделать, если урожай считает клиент.
- Два режима, и ручной не обязателен. Это снижает порог и не наказывает стратега.
- Общий постоянный мир и офлайн-время дают причину возвращаться без энергетических штрафов, если не испортить это таймерами.
- Вертикальные срезы уже нарезаны: первый реально маленький.
- Админка как часть каждой механики защищает от зашитых в код цен.
- Запрет на языковые модели в сельскохозяйственном тике экономит деньги и делает симуляцию повторяемой.
- Монетизация заранее ограничена: нет покупки доминирования и бесконечных ресурсов.

## Слабые стороны

- Объём систем равен нескольким играм. Пока нет жёсткого «не делаем в этом году», команда из ИИ будет распухать спецификациями.
- Реальная география легко превращается в обещание, которое нельзя удержать на Android. Поэтому карта — первый вопрос, а не декорация.
- «Живые ИИ-фермеры с памятью и отношениями» в первой версии почти всегда либо мёртвые, либо дорогие. В постановке это уже смягчено автоматами, но ожидание нужно явно снизить до D8.
- Две валюты, кредиты, налоги, аукционы и кооперативные склады вместе создают дыры. Их нельзя проектировать одним абзацем.
- Сюжет на 10 глав при пустом прототипе отвлекает. Для среза №1 достаточно одного наставника и пяти минут.
- Реальные марки техники юридически опасны. Вымышленный парк на старте — рекомендация, не решение.
- Нет ни одной цифры, которую уже можно считать утверждённой: капитал, сутки, год, урожай. Это правильно на этом шаге, но без ответов D2–D5 GDD будет фикцией.

## Технические риски

| Риск | Почему | Что делаем |
|---|---|---|
| Непрерывный 3D на всю республику | Память, стриминг, контент | Не выбирать молча. Q-WORLD-001 |
| Godot 4.8 beta | Подвижный API | Кандидат только 4.7.2, пока нет stable 4.8 |
| Смена рендерера на устройстве | Часто нужен перезапуск, часть функций Mobile отличается | Не обещать переключатель Vulkan/GL |
| Рассинхрон ручной техники | Клиент рисует плавно, сервер решает результат | Сервер принимает операцию по правилам участка, не по «красоте» колеи |
| Двойной тап и повтор пакета | Деньги и урожай удваиваются | Ключ идемпотентности на каждую хозяйственную команду |
| Админка пишет в таблицы | Обход правил, порча мира | Команды домена, черновик → публикация |
| Секреты в репозитории | Утечка подписи и БД | `.gitignore`, ключ подписи вне git |
| ODbL | Производная база карты может обязанно публиковаться | Юридическая проверка до импорта, не в этом коммите |

## Экономические риски

- Замкнутые цепочки без стока печатают деньги: зерно → корм → молоко → деньги → зерно.
- ИИ-скупщик с бесконечным кошельком является принтером. ИИ-скупщик с нулевым кошельком убивает рынок при малом онлайне.
- Новый игрок в «плохом» районе навсегда отстаёт, если бонус района слишком сильный.
- Торговля между игроками без ограничений выводит ценность стартовых квестов.
- Платное ускорение, если его разрешат, становится обязательным налогом.

Защита проектируется в D3–D4 и проверяется отдельным симулятором, которого ещё нет. Пока симулятора нет, нельзя объявлять баланс готовым.

## Риски масштаба

Постановка описывает продукт на несколько лет. Репозиторий пустой. Единственный безопасный масштаб сейчас — этап 0 и очередь вопросов. Оценка «тысячи одновременных игроков на VPS 4 vCPU / 8 ГБ» не делается: постановка прямо запрещает утверждать это без измерений. Ориентир VPS годится только как стенд.

Контент республики (районы, сёла, дороги, почвы) нельзя нарисовать вручную под каждый населённый пункт до выбора масштаба карты.

## Приоритеты

1. Закрыть D1. От карты зависят ассеты, сервер мира и срез №5.
2. Закрыть D2 и D3. Без времени и денег нельзя писать формулы урожая.
3. Зафиксировать срез №1 как продукт: одна культура, одна операция, сохранение, повторный вход.
4. Полный GDD писать системами из каталога, но детально только для того, что входит в ближайшие два среза. Остальное — контракт и граница, без сотен полей.
5. Код, Docker и админка — после утверждённой архитектуры этапа 2.

## Что сознательно не решено этим документом

Способ карты, длина года, валюта, глубина агрономии, физика, шарды, глубина ИИ, VIP, рендерер. Всё это в `docs/design/`.
