# Работа нескольких ИИ

Проект рассчитан на Codex, Claude и Grok. Сторонние наборы навыков не установлены: их содержимое и лицензии не проверялись, а постановка запрещает ставить их автоматически.

## Кто что делает лучше

Это распределение по типу задачи, не запрет. Любой ИИ может сделать соседнюю работу, если в задаче указан путь и проверка.

| Задача | Предпочтительный исполнитель | Почему | Что читать |
|---|---|---|---|
| Ответ владельцу, фиксация решения, целостность GDD | Grok или Claude | Длинный контекст постановки и противоречия | `START.md`, `DECISIONS.md`, активный `docs/design/D*.md` |
| Спецификация системы, диалоги, тексты UI | Claude | Длинные связные тексты | Один файл системы и `SYSTEMS_CATALOG.md` по этой строке |
| Godot, GDScript, сцена, ввод | Codex | Точечные правки в проекте | Фаза среза, `docs/architecture`, только затронутые сцены |
| Go, PostgreSQL, миграции, транзакции | Codex | Код и тесты рядом | Фаза среза, контракт API этой системы |
| Админка React | Codex | То же | Раздел админки в спецификации фичи |
| Баланс и экономический симулятор | Отдельная задача, любой | Нужны тесты, не вкус | `docs/economy` когда появится, плюс журнал операций |
| Ревью безопасности экономики | Не тот же коммит, что реализация | Иначе исполнитель не увидит свой обход | Diff, тест на повтор и отрицательный баланс |
| Документация после смены решения | Тот, кто принял ответ владельца | Иначе решение потеряется в чате | Шаблон в `DECISIONS.md` |

## Навыки, которые нужны, но не установлены

Исполнитель использует собственные знания и официальную документацию. Не скачивать произвольные skill-репозитории.

| Область | Что считать источником | Чего не делать |
|---|---|---|
| Godot 4.7 | docs.godotengine.org ветки 4.7 | Не переносить советы Godot 3 и не включать 4.8-only API |
| GDScript | Та же документация | Не писать логику денег на клиенте |
| Go | go.dev, стандартная библиотека | Не тащить микросервисный каркас |
| PostgreSQL | postgresql.org | Не хранить деньги в `float` |
| React + TypeScript | Документация выбранной версии, когда она будет зафиксирована | Не подключать админку к БД напрямую |
| Android | Экспорт Godot и проверка на устройстве | Не обещать Vulkan без теста |
| Экономика | Свой симулятор в `tools/` и тесты инвариантов | Не балансировать «на глаз» в проде |

## Как передавать задачу

В задаче должны быть:

1. Цель одним абзацем.
2. ID этапа и статус, который ожидается на выходе.
3. Список файлов, которые можно менять.
4. Список файлов, которые читать.
5. Запрет на области (например «не трогать рынок»).
6. Команда проверки или честное «проверять нечем, статус не выше PARTIAL».
7. Как обновить `ROAD.md`.

Исполнитель не расширяет задачу «заодно».

## Как проверять

- Документация: ссылки из `ROAD.md` открываются, статус в шапке файла совпадает с таблицей в `ROAD.md`.
- Решение: в `DECISIONS.md` есть полный вопрос и полный ответ, статус `APPROVED`.
- Код, когда он появится: тесты из файла этапа, миграции на чистой базе, повтор той же экономической операции не удваивает результат.
- Нельзя писать «тесты прошли», если команда не запускалась.

## Конфликты

- Две ветки не правят один GDD-файл без владельца слияния.
- `DECISIONS.md` меняет только тот, кто только что получил ответ владельца, либо владелец явно поручил правку.
- Если в чате решение есть, а в git его нет, для следующего ИИ решения не существует.

## Фиксация работы

Коммит содержит зачем, а не только что. В сообщении есть ID вопроса или этапа. После пуша в отчёте владельцу: SHA, список файлов, что не сделано, какой следующий вопрос или шаг.
